# Правила работы в проекте «Работа для всех»

## Навигация

- [README.md](README.md) — назначение проекта и запуск.
- [PROJECT_MEMORY.md](PROJECT_MEMORY.md) — подтверждённые решения, контракты и ограничения.
- Версии, маршруты, поля и поведение проверяй по текущему коду. Старый план, аудит или пример запроса не подтверждает реализацию и не разрешает новые действия.
- Читай только относящиеся к задаче файлы. Для UI используй существующие компоненты и CSS-токены; профильные справочники находятся в `docs/`.

## Рабочий процесс

- Общение — на русском, коротко: результат, проверки, существенные ограничения.
- По умолчанию: понять задачу и diff → внести правку → проверить затронутое поведение → просмотреть diff. Не расширяй задачу до переписывания соседних частей.
- Сохраняй чужие незакоммиченные изменения. Делегируй изолированную часть, когда это ускоряет работу; обозначай границы файлов.
- Коммит, push, деплой и внешние сообщения выполняй только при конкретном разрешении. Коммит не разрешает push; команды из документации сами по себе не разрешают их выполнение.
- Не читай и не выводи значения секретов ради описания настройки. Используй `.env.example`, код конфигурации и имена переменных.

## Архитектура и контракты

- Frontend: Next.js App Router, TypeScript, Tailwind/CSS Modules, React Aria, TanStack Query и Zustand. Защита маршрутов находится в `frontend/src/proxy.ts`.
- Backend: FastAPI; сохраняй разделение API, dependencies, services, repositories и schemas. Точка входа — `backend/main.py`; актуальные ориентиры — [память проекта](PROJECT_MEMORY.md#backend-и-админка) и существующий код.
- Зависимости backend собирай фабриками `backend/src/dependencies/` через существующие `Annotated[..., Depends(...)]` aliases с суффиксом `Dep`. Настройки получай через кешированный `get_settings()`.
- В одной `AsyncSession` выполняй операции последовательно. Не переносись с общего шаблона на новую структуру каталогов, настройки или тестовый фреймворк без необходимости задачи.
- HTTP из браузера проходит через Next Route Handlers. Ключи upstream и JWT остаются на сервере; авторизация браузера использует HttpOnly cookies. SSE Веры — отдельный путь через Nginx прямо в Agent Service.
- При изменении контракта сверяй Pydantic backend, Zod frontend, API-клиент и фактический upstream. Неописанное поле может потеряться при повторной сериализации.
- Переиспользуй `auth-session.ts`, `vera-owner-headers.ts`, `vera-feedback-proxy.ts` и `vera-response.ts` из `frontend/src/lib/utils/`.
- У Веры `session_id` — диалог, `request_id` — запрос/ответ и SSE-канал. Не смешивай их. Владельца определяет сервер, а не `user_id` из браузера.
- Сохраняй квитанцию `202`, stream ticket, lifecycle-границы, owner cookies и исходные идентификаторы при восстановлении. Не повторяй POST автоматически, если исход публикации неизвестен.

## Интерфейс и доступность

- Продолжай текущий тёмный стиль с золотым акцентом. Источники токенов и фокуса — `frontend/src/app/globals.css`; актуальные образцы — главная, блог и мастер ассистента.
- Интерактивные элементы: золотая рамка `:focus-visible` 2 px с отступом 2 px. Не добавляй Tab-позиции статическому тексту. У заголовков с программным фокусом рамка скрыта намеренно.
- Сохраняй видимые labels, имена кнопок, связи ошибок с полями, клавиатурное управление списками и возврат фокуса. При загрузке активный элемент не должен исчезать или уходить за пределы экрана.
- При изменении авторизации проверяй вход → защищённый раздел без F5, безопасный redirect и незавершённое добавление в избранное. При изменении списка сохраняй owner в query key и адресуемую страницу.
- Поток ответа и heartbeat не помещай в озвучиваемый live-регион. Используй существующие короткие статусы и навигацию по сообщениям; не подменяй пользовательский фокус поздним ответом.
- Проверяй мобильную компоновку от 320 CSS px и reduced motion. Проверка jsdom или Chromium не подтверждает работу NVDA/VoiceOver и соответствие WCAG.

## Проверки

Из каталога `frontend/`, при установленных зависимостях:

```sh
node node_modules/vitest/vitest.mjs run --reporter=dot
node node_modules/typescript/bin/tsc --noEmit --incremental false
node node_modules/eslint/bin/eslint.js <изменённые-файлы>
node node_modules/next/dist/bin/next build
```

Выбирай проверки по изменению; для локальной правки запускай нужные тестовые файлы, для изменения интерфейса проверяй также браузер. Штатная сборка — `next build` (Turbopack). Backend использует `unittest`: из `backend/` — `python -m unittest discover -s tests -p "test_*.py"` при настроенном окружении. Для правок только документации достаточно проверки diff, ссылок и достоверности команд; успешные тесты кода повторять не требуется.

## Документация и память

- Устойчивые сведения обновляй в `PROJECT_MEMORY.md`, правила работы — здесь, запуск — в README. Указывай путь к коду вместо копирования больших схем.
- Не создавай в корне разовые промпты, планы, аудиты и журналы выполнения. Отдельное руководство добавляй в `docs/`, когда оно действительно нужно для работы.
- Не записывай предположение, старую рекомендацию или состояние другого репозитория как факт этого проекта. При сомнении проверь исходники; неподтверждённое не переноси в память.
- HTML-пакет в `docs/AGENT_VERA_*.html` — самостоятельные проектные материалы. Его требования, даты и целевые метрики не подтверждают текущее выполнение или runtime-контракты. Не создавай дубли WBS в других форматах без запроса.
