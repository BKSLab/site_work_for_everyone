# Задание исполнителю — прогон 13 (источники ответа и отмена)

Сначала прочитай `PROMPT_COMMON.md`. Ниже только специфика прогона.

## Предусловие

Прогоны 7 и 10 должны быть завершены. VERA-009 опирается на схемную валидацию
результатов инструментов из VERA-021, а VERA-017 — на клиентскую state machine
из VERA-025. Без них обе карточки придётся переделывать.

## Скоуп

Строго две карточки, строго в этом порядке:

1. **VERA-009** — структурированные источники не доходят до frontend (P2)
2. **VERA-017** — явная отмена отсутствует (P2)

Затрагиваются Agent Service и frontend.

## Ключевые решения — реализуй их, не изобретай свои

### VERA-009

- **Источники отдаются наружу в нормализованном виде** в терминальном
  SSE-событии и в ответе истории. Сейчас они сохраняются в PostgreSQL, но не
  возвращаются никуда, и пользователь получает только сгенерированный абзац
  «Основание», корректность которого держится на промпте.
- **Валидация на стороне Agent Service, а не на клиенте.** Схема результата
  инструмента уже введена в VERA-021 — переиспользуй её, не пиши вторую.
- **Текстовое «Основание» остаётся** как читаемая часть ответа, но перестаёт
  быть единственным и машинно непроверяемым источником.
- **Вложения не добавляются.** Сейчас их согласованно нет на всех слоях;
  добавление файлов требует отдельного контракта загрузки, хранения,
  антивирусной проверки и доступа. Бинарные данные через SSE не передавать.

### VERA-017

- **Сетевой обрыв не является отменой.** Это не дефект, а осознанное решение:
  продолжение обработки позволяет сохранить ответ для истории и повторного
  подключения. Не связывай отмену с закрытием соединения.
- **Отмена — явная команда** с отдельным endpoint и состоянием, которое
  consumer проверяет между узлами графа. Результат сохраняется статусом
  `cancelled` — он уже заведён в номенклатуре delivery state machine и до сих
  пор выставлялся только при остановке сервиса.
- **Разделяй безопасно отменяемые этапы и уже начатые операции с внешним
  эффектом.** После начала отправки консультации отмена не должна обещать
  пользователю, что письмо не ушло: интерфейс обязан сказать правду.
- **Кнопка «Остановить»** появляется во время ожидания и стриминга и исчезает
  на терминальном событии.

## Вне скоупа

- вложения к сообщениям в любом виде;
- изменение набора терминальных событий и delivery state machine;
- отмена уже завершённых запросов и удаление их результатов;
- retry-UX сверх повторной отправки того же вопроса.

## Тесты

- нормализованные источники приходят в терминальном событии и в истории;
- некорректный элемент источников отвергается на стороне Agent Service;
- UI показывает источники отдельным блоком и не ломается при их отсутствии;
- отмена до первого токена завершает запрос статусом `cancelled`;
- отмена после начала отправки консультации не утверждает, что письмо не ушло;
- сетевой обрыв по-прежнему не отменяет обработку;
- терминальное событие приходит ровно одно в каждом сценарии.

## Завершение

Сводка по обеим карточкам плюс подтверждение: источники проверяются схемой на
сервере, а отмена никогда не обещает отката уже выполненного внешнего действия.
