# Задание исполнителю — прогон 8 (жизненный цикл диалога)

Сначала прочитай `PROMPT_COMMON.md` — общие правила, процесс, отчёты, тесты и
стоп-условия. Ниже только то, что специфично для этого прогона.

## Скоуп

Строго две карточки, строго в этом порядке:

1. **VERA-005** — PostgreSQL history и Redis memory имеют разный жизненный цикл (P1)
2. **VERA-029** — нет явного создания и закрытия диалога (P2)

Порядок обязателен: VERA-029 даёт пользователю управление границей диалога,
которая определяется серверной семантикой из VERA-005. Обратный порядок
означает интерфейс поверх неопределённого понятия.

Затрагиваются Agent Service и frontend. `nginx/` не трогать.

## Ключевые решения — реализуй их, не изобретай свои

Карточка VERA-005 предлагает три варианта семантики. **Выбран первый:** при
истечении Redis TTL текущая PostgreSQL-сессия закрывается и создаётся новая.

Обоснование: восстановление bounded context из завершённых turns выглядит
дешевле, но создаёт худший из миров — пользователю показывается непрерывная
беседа, а модель получает урезанную выжимку и отвечает так, будто помнит
больше, чем помнит. Честная граница лучше поддельной непрерывности.

Отсюда конкретика:

- **Сервер — единственный владелец срока жизни сессии.** Активной считается
  сессия с `closed_at IS NULL` и `last_activity_at` не старше того же TTL,
  что и Redis-checkpoint (24 часа неактивности). Значение берётся из одной
  настройки, а не дублируется двумя числами в разных сервисах.
- **Frontend перестаёт ротировать `session_id` по собственным часам.** Сейчас
  он сравнивает `createdAt` из `sessionStorage` с 24 часами и может начать
  новый диалог, пока Redis ещё держит контекст. Срок жизни приходит с сервера.
- **Закрытие сессии выставляет `closed_at`.** Поле есть в модели и не
  используется нигде, кроме выборки активной сессии.
- **При обращении к сессии, чей контекст истёк,** сервер закрывает её и
  возвращает идентификатор новой; клиент показывает явную границу диалога.

Для VERA-029:

- добавь `POST /sessions` и `POST /sessions/{id}/close` в Agent Service, с той
  же проверкой владельца, что и у истории;
- кнопка «Новый диалог» во фронтенде закрывает текущую сессию и начинает
  новую;
- **политика при входе после анонимного чата:** продолжается текущий
  анонимный диалог с присвоением его вошедшему пользователю. Механизм
  присвоения уже существует в `start_turn` и повторно не проектируется.
  Открывать вместо этого старую auth-сессию нельзя: пользователь потеряет
  разговор, который видит перед собой.
- в интерфейсе видна граница контекста: где закончился предыдущий диалог.

## Вне скоупа

- восстановление контекста из завершённых turns в любом виде;
- изменение формата истории и SSE-событий;
- удаление диалогов и retention — это VERA-023;
- изменение owner-семантики и механизма присвоения анонимной сессии.

## Тесты

Обязательны интеграционные на реальных PostgreSQL и Redis:

- auth-сессия после 24 часов неактивности: старая закрыта, выдана новая;
- активная анонимная сессия старше 24 часов от создания, но с недавней
  активностью, не ротируется;
- явное закрытие выставляет `closed_at` и исключает сессию из активных;
- вход после анонимного чата продолжает тот же диалог, а не подменяет его;
- чужая сессия при закрытии по-прежнему получает `403`.

Фронтенд: тесты на отсутствие клиентской ротации по таймеру и на отображение
границы диалога.

## Завершение

Сводка по обеим карточкам плюс подтверждение: срок жизни сессии задаётся одной
настройкой и одинаково понимается PostgreSQL, Redis и фронтендом.
