Назначение документа

Документ переводит цели итерации 1 (паспорт проекта, раздел 5) в проверяемые критерии приёмки: что именно проверяется, каким методом, кто отвечает за измерение и какой результат считается успешным. Каждый критерий помечен приоритетом по шкале MoSCoW в части Must/Should — недостижение Must-критерия означает отказ в приёмке итерации, недостижение Should — условную приёмку с фиксацией доработки.

Must — обязателен для приёмки
Should — целевой ориентир, условная приёмка
1

Функциональные критерии

Критерий Метод проверки Порог / результат Приоритет
Ответ агента содержит ссылку на источник из базы знаний Ручная проверка на тестовом наборе вопросов (PM + тестировщик) 100% ответов — с указанием источника, либо явный отказ Must
Корректный отказ на вопросы вне тематики БЗ Тестовый набор «вне домена» (10–15 вопросов), ручная проверка Нет «выдуманных» ответов — агент сообщает об отсутствии информации Must
Доступ к чату без регистрации Прогон сценария от анонимного пользователя Полный цикл «вопрос → ответ» без авторизации Must
Потоковая передача ответа (SSE) Визуальная проверка появления токенов «на лету» Токены отображаются постепенно, не одним блоком Should
Корректная деградация при пустом результате поиска Сценарий с заведомо отсутствующим в БЗ запросом Понятное сообщение пользователю, без зависания/ошибки 500 Must

Качество и точность ответов

Критерий Метод проверки Порог / результат Приоритет
Релевантность ответов на фиксированном тестовом наборе Заранее согласованный с заказчиком набор из 50–100 вопросов; бинарная разметка «релевантно / нет» силами PM + контент-эксперта ≥ 80% релевантных ответов Must
Юридическая достоверность контента базы знаний Подписанный протокол проверки контент-экспертом (юристом) с указанием версий/редакций НПА Протокол подписан, действующие редакции ТК РФ и ФЗ-181 подтверждены Must
Покрытие базы знаний Сверка перечня загруженных документов со списком в ТЗ ТК РФ + ФЗ-181 + не менее 5 авторских статей, проиндексированы и доступны поиску Must
Согласованность ответов на близкие переформулировки вопроса 3–5 пар переформулированных вопросов из тестового набора Источник и суть ответа совпадают для одного и того же вопроса Should

Нефункциональные критерии

Критерий Метод проверки Порог / результат Приоритет
Время до первого токена ответа (TTFT) Замер на тестовом наборе вопросов в приёмочном окне ≤ 5 секунд (медиана по набору) Must
Доступность сервисов во время приёмочного теста Мониторинг (Phoenix) за фиксированное окно приёмки (например 5 рабочих дней) 100% uptime трёх сервисов в окне приёмки Must
Контролируемая деградация при сбое инфраструктуры Контролируемое отключение RabbitMQ/Qdrant в тестовой среде Понятная ошибка пользователю, retry/dead-letter работает, нет потери сообщений Should

Доступность интерфейса чата

Целевая аудитория платформы — пользователи скринридеров, поэтому интерфейс чата проверяется отдельно от общего дизайна сайта.

Критерий Метод проверки Порог / результат Приоритет
Соответствие WCAG 2.2 AA для виджета чата Автоматический аудит (axe/Lighthouse) + ручная проверка Нет критичных нарушений уровня AA Must
Работа со скринридером Ручное прохождение сценария «вопрос → ответ» с NVDA или JAWS Вопрос, статус загрузки и ответ корректно озвучиваются, фокус управляется предсказуемо Must
Управление с клавиатуры Прохождение сценария без мыши Все элементы виджета доступны по Tab, видимый фокус Must
5

Процедура приёмки (UAT-гейт)

Тестовый набор вопросов и протокол релевантности согласуются с заказчиком до начала приёмочного тестирования (а не постфактум)
Демонстрация проводится живьём в присутствии заказчика на согласованном наборе — не только по отчёту
Переход к фазе «Запуск» возможен только при выполнении всех Must-критериев данного документа
При выполнении Must, но недостижении одного или нескольких Should — допускается условная приёмка с фиксированным сроком доработки
Результаты проверки по каждому критерию прикладываются к акту приёмки как обязательное приложение

Акт приёмки итерации 1 подписывается заказчиком только при наличии заполненной таблицы по всем разделам 1–4 с фактическими значениями против целевых.
